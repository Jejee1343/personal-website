# personal-website

Source for **Jeerawan Jampit**'s website — built with [Quarto](https://quarto.org),
published with GitHub Pages, served at **jeerawanjampit.com**.

---

## The routine (every time you change something)

**1. Render.** In RStudio press the **Render** button, or in Terminal:

```bash
cd ~/Documents/personal-website
quarto render
```

This rebuilds the whole site into the `docs/` folder.

**2. Push.** Open **GitHub Desktop**. It shows your changed files.
Type a short summary ("added new post"), click **Commit to main**,
then click **Push origin**.

That's it. The site updates within a minute or two.

> While you are writing, `quarto preview` in Terminal gives you a live preview
> that refreshes as you save. Press Ctrl+C to stop it. Preview does not publish
> anything — you still need Render + Push.

## Adding a blog post

1. Make a folder: `posts/my-post-name/`
2. Put an `index.qmd` inside it, starting with:

```yaml
---
title: "My post title"
description: "One sentence that shows on the blog list."
author: "Jeerawan Jampit"
date: "2026-09-15"
categories: [econometrics, R]
---
```

3. Write below that. Render, then push.

The post shows up on the Blog page by itself — there is no list to edit.

## Adding a portfolio project

Same idea, in `projects/`:

1. Make a folder: `projects/my-project/`
2. Add `index.qmd` with the same kind of front matter, plus
   `image: thumbnail.png` if you have a picture (a chart works well).

## Making code actually run

The example project shows code as plain text. To have Quarto **run** the code
and show its output, put curly braces on the fence:

````
```{r}
library(ggplot2)
ggplot(mpg, aes(displ, hwy)) + geom_point()
```
````

For R you need `rmarkdown` and `knitr`:

```r
install.packages(c("rmarkdown", "knitr"))
```

For Python you need Jupyter:

```bash
pip install jupyter
```

Handy chunk options, written just inside the chunk:

```
#| echo: false      # hide the code, show only the output
#| warning: false   # hide warnings
#| fig-cap: "A caption for the figure"
```

`execute: freeze: auto` is already set in `_quarto.yml`, so Quarto only re-runs
a document's code when that document itself changes. Renders stay fast.

## What each file does

| File | Purpose |
|------|---------|
| `_quarto.yml` | Site-wide settings: title, navbar, theme, footer |
| `styles.scss` | Colors and fonts. Change `$primary` to change the accent color |
| `index.qmd` | Home page |
| `about.qmd` | About page |
| `cv.qmd` | CV page |
| `portfolio.qmd` | Portfolio listing (reads from `projects/`) |
| `blog.qmd` | Blog listing (reads from `posts/`) |
| `CNAME` | The custom domain. Do not delete |
| `.nojekyll` | Tells GitHub not to reprocess the site. Do not delete |
| `docs/` | The built site. Generated by Quarto — never edit by hand, but **do** commit it |

**Important:** `docs/` must be committed and pushed. That folder *is* the live
website. If you push only the `.qmd` files, nothing on the site changes.

## How the custom domain works

Two pieces:

1. The `CNAME` file here, which Quarto copies into `docs/` on every render.
2. A DNS record at GoDaddy — type `CNAME`, name `quarto`, value
   `Jejee1343.github.io`.

To move the site to the bare domain `jeerawanjampit.com` later: change the
`CNAME` file to `jeerawanjampit.com`, update GitHub → Settings → Pages, and at
GoDaddy replace the record with four `A` records pointing to `185.199.108.153`,
`185.199.109.153`, `185.199.110.153`, `185.199.111.153`, plus a `www` CNAME to
`Jejee1343.github.io`.

## If something breaks

**Changes don't show on the site** — did you render *and* push? Check that
GitHub Desktop shows files inside `docs/` in the commit. Then hard-refresh the
page with Cmd+Shift+R.

**The domain shows a 404** — check GitHub → repo → Settings → Pages: source
should be `main` / `/docs`, and the custom domain should read
`jeerawanjampit.com`.

**A new page doesn't appear** — for posts and projects it must be its own folder
containing a file named exactly `index.qmd`.

**Render fails with an error about a package** — install the package it names,
then render again.
